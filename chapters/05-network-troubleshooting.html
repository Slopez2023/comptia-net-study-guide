Network Troubleshooting

Everything you've learned, used as a symptom → cause → fix chain. Memorize the 7 steps word for word, then learn to read a symptom and pick the tool.

  • 5 lessons
  • Days 10–11 · Nov 24–25
  • High-yield: the 7 steps · interface counters · commands

Recite CompTIA's 7 troubleshooting steps in order, and answer "what should the tech do NEXT?" questions.

  1. Identify the problem
    Gather info, question users, identify symptoms, ask what changed, duplicate the problem, take multiple problems one at a time
  2. Establish a theory of probable cause
    Question the obvious. Work the OSI model top-down or bottom-up, or divide and conquer
  3. Test the theory
    Confirmed → next steps. Not confirmed → new theory or escalate
  4. Establish a plan of action and identify potential effects
  5. Implement the solution or escalate
  6. Verify full system functionality and implement preventive measures
  7. Document findings, actions, outcomes and lessons learned
Mnemonic

Identify · Establish · Test · Establish plan · Implement · Verify · Document
"I Eat Tacos Every Instant, Very Delicious."

Watch for
  • The question tells you which step you're on. Answer with the next step, not the final fix.
  • Documentation is last, after verifying. "Implement preventive measures" belongs to step 6.
  • A fix that could affect other systems → step 4 (plan and identify effects) or change management.

Read interface counters and port status, and diagnose cable, PoE and transceiver problems.

Symptom / counterLikely cause
CRC errorsCorrupted frames: a bad cable or connector, interference, or a duplex mismatch
Runts (< 64 bytes)Collisions or a duplex mismatch
Giants (> 1518 bytes)MTU / jumbo frame mismatch
DropsCongestion, buffers full
Late collisionsDuplex mismatch or a cable that's too long
Error disabledA security feature shut the port (port security, BPDU guard). Fix the cause, then reset the port
Administratively downSomeone ran shutdown. Fix with no shutdown
SuspendedA link aggregation (LACP) member didn't match its partner
AttenuationSignal gets weaker over distance (cable too long, over 100 m)
CrosstalkSignal bleeds between pairs (untwisted too far at the termination). NEXT/FEXT
Interference (EMI)Running near motors or fluorescent lights. Use STP or fiber
TX/RX transposedTransmit and receive swapped, so there's no link. Use a crossover cable or swap the fiber strands
PoE budget exceededThe switch can't power all devices, so new ones won't power on
Wrong PoE standard802.3af = 15.4 W · at (PoE+) = 30 W · bt (PoE++) = 60/100 W
  • Wrong cable: single-mode optics on multimode fiber (or the reverse) → no link or errors. Cat 5e on a 10G run → slow or errors. Use STP in high-EMI areas.
  • Transceivers: both ends must match (speed, wavelength, SMF/MMF). Low signal strength (dBm) → dirty connectors, bends, or the fiber run is too long.
  • Improper termination = a bad crimp or the wrong pinout (T568A vs B). Test with a cable tester.
Watch for

A new PTZ camera won't power on, but other phones work → PoE budget or it needs PoE+/++. CRC errors climbing on one port → swap the cable first.

Diagnose STP, VLAN, ACL, routing and addressing problems from symptoms.

SymptomCauseFix
Network crawls, broadcast storm, MAC table flappingSwitching loop (STP off or misconfigured)Enable STP / BPDU guard
Traffic takes a strange path through an old switchWrong root bridge electedSet a lower priority on the core switch
Host gets the wrong subnet, can't reach its peersWrong VLAN on the access portAssign the correct VLAN
Can ping by IP but one app or port failsACL blocking that portFix the rule order or add an allow rule
Reaches the local subnet but not the internetWrong or missing default gateway or default routeFix the gateway / add 0.0.0.0/0
New devices get 169.254.x.xDHCP pool exhausted (or the server is unreachable)Enlarge the scope or shorten leases
Connectivity drops in and out, "address conflict" warningDuplicate IPFind it with arp, use a reservation or exclusion
Can reach some local hosts but not othersWrong subnet maskCorrect the mask
Watch for

"Can't reach anything off the subnet" → the gateway. "Can't reach anything at all, and has an APIPA address" → DHCP. Read the symptom carefully.

Tell latency, jitter, packet loss and bandwidth problems apart, and fix common Wi-Fi issues.

LatencyDelay. Each packet takes a long time to arrive (high ping ms)
JitterVariation in delay → choppy VoIP and video. Fix with QoS
Packet lossPackets never arrive → retransmits, gaps
Bandwidth vs throughputBandwidth = the pipe size. Throughput = what you actually get
Congestion / contentionToo many users on a shared link at the same time
BottleneckOne slow link or device limits the whole path
Wi-Fi symptomCause → fix
Slow near other APsChannel overlap → use 1/6/11 on 2.4 GHz, narrower widths
Weak signal in some roomsInsufficient coverage or attenuation (walls) → site survey, add or move APs
Clients keep dropping offDisassociation: interference, low signal, or a deauth attack
Calls drop when walking between APsRoaming misconfiguration → same SSID and security everywhere, tune AP power
Watch for

Choppy voice but downloads are fine → jitter → QoS. Strong signal but still slow → interference / channel overlap, not coverage.

Open Terminal and run these. Seeing real output makes the commands stick:

ping -c 4 1.1.1.1 · traceroute 8.8.8.8 · dig comptia.org MX · nslookup comptia.org · arp -a · netstat -rn · ifconfig en0 · sudo tcpdump -i en0 -c 20

Watch for
