Explain how a router picks a route (longest prefix → AD → metric), compare OSPF/EIGRP/BGP, and know NAT vs PAT and FHRP.

The job: A router moves packets between IP networks. It must select one usable path, translate addresses when a private network reaches the internet, and keep a default gateway available when a router fails.

Static routes and learned routes

A static route is an entry an administrator adds by hand. It is a good fit for a small branch, a path to a single server network, or a default route toward an ISP. Static routes do not discover failures or new paths on their own, so the administrator must maintain them.

Dynamic routing lets routers exchange reachability information. BGP carries routes between autonomous systems, such as an organization and an ISP. OSPF is an open link-state protocol that builds paths within an organization. EIGRP is an advanced distance-vector protocol, most often seen in Cisco-heavy networks.

Use BGP when the question crosses organizational or provider boundaries. Use OSPF for a large internal network that needs an open standard. A static route is often the simplest answer for one predictable exit path.

How a router chooses one route

First, the router compares the destination address with every matching route and chooses the longest prefix. A route for 10.20.30.0/24 beats a default route because it describes a smaller, more specific destination range. This rule comes before every other comparison.

If two sources advertise the same prefix, the router uses administrative distance, or AD, to choose the source it trusts more. Lower AD wins. A connected route has AD 0, a static route normally has AD 1, and OSPF normally has AD 110. AD compares different route sources, not two paths learned by the same protocol.

Finally, if the competing routes came from the same protocol and have the same prefix length, the router uses that protocol's metric. OSPF calls its metric cost. EIGRP considers bandwidth and delay by default. A metric tells a protocol which of its own paths it prefers.

Route choice order is prefix length, then administrative distance, then metric. Do not pick the lowest metric until the first two tests have tied.

Analogy

Think of a delivery driver reading directions. A street address is better than a city name, so it matches the longest prefix. If two trusted map services give the same street, the driver uses the service they trust more, like AD. If one service gives two routes, the shorter route is its metric choice. Routers compare numeric route data, not maps or travel time.

Address translation and gateway backup

NAT changes an address as traffic crosses a boundary, commonly between private IPv4 space and a public address. PAT is a form of NAT that also uses port numbers. Many inside hosts can share one public IPv4 address because each connection has a different translated source port.

Hosts need one default gateway address. A First Hop Redundancy Protocol, or FHRP, lets two or more routers present a shared virtual IP, or VIP, as that gateway. One router forwards traffic. If it fails, another router takes the VIP and hosts keep using the same gateway address.

NAT changes IP addressing. PAT lets many inside sessions share one public address by tracking ports. FHRP does neither. It protects the first router a host uses to leave its local subnet.

Subinterfaces carry VLAN traffic

A physical router port can use subinterfaces to route for several VLANs. Each logical subinterface has a VLAN tag and an IP address for that VLAN, while the physical link connects to a switch trunk. This design is called router on a stick. A layer 3 switch can do the same job with switch virtual interfaces instead.

A story: Priya sends a packet to the internet

  1. Priya's laptop sends web traffic to its default gateway, the FHRP virtual IP for its VLAN.
  2. The active router looks up the public destination. No internal prefix matches, so it selects 0.0.0.0/0, the default route to the ISP.
  3. The router translates Priya's private source address and source port through PAT before sending the packet outward.
  4. When the active router fails, the standby router takes the VIP. Priya keeps the same gateway setting and new traffic continues through the backup.

Configure VLANs, trunks (802.1Q, native VLAN), voice VLANs, link aggregation, speed/duplex and jumbo frames, and explain how STP stops loops.

The job: Switching separates devices into the right local networks, carries those networks between switches, and prevents redundant cabling from becoming a traffic loop.

VLANs and their layer 3 doorways

A VLAN splits one physical switch into separate broadcast domains. A device in VLAN 10 does not receive broadcasts from VLAN 20, even when both plug into the same switch. Administrators create VLANs in the VLAN database, then assign access ports to the right VLAN.

A VLAN needs layer 3 routing to reach another VLAN. A switch virtual interface, or SVI, is a logical interface such as interface vlan 10 with an IP address. On a multilayer switch, SVIs can route between VLANs. An SVI can also give a layer 2 switch a management address.

A VLAN is a layer 2 broadcast domain. An SVI is a layer 3 interface associated with a VLAN. Creating a VLAN alone does not provide inter-VLAN routing.

Access links, trunks, and phones

An access port normally carries one VLAN and sends ordinary Ethernet frames without VLAN tags to its endpoint. A trunk carries traffic for multiple VLANs between network devices. 802.1Q adds a VLAN tag so the receiving switch can keep each frame in the correct VLAN.

One VLAN on a trunk is the native VLAN. Its frames are untagged, so the native VLAN setting must match on both ends. Use an unused VLAN rather than VLAN 1 where the design permits, and disable unused switch ports to reduce trunking and VLAN-hopping mistakes.

A phone port can carry two VLANs. The phone tags its voice traffic for the voice VLAN, while the attached computer uses the data VLAN through the phone. This keeps voice traffic separate while using one wall jack.

Access port means one untagged VLAN for an endpoint. A trunk uses 802.1Q tags for many VLANs, except for the native VLAN. A voice VLAN and data VLAN can share a phone port.

Analogy

Picture a mailroom. An access port is a mailbox for one department. A trunk is a delivery cart that carries labeled envelopes for many departments. The native VLAN is the one department whose envelopes have no label. Real switches use frame headers and forwarding tables, not people reading envelopes.

Links must agree at both ends

Link aggregation bundles physical switch links into one logical connection. LACP negotiates the bundle and provides more capacity plus a backup link. Both ends must agree on the aggregation settings, and traffic is distributed across member links rather than splitting one conversation across every cable.

Speed and duplex must also match. Modern Ethernet normally uses auto-negotiation and full duplex. A mismatch can cause errors, late collisions, and slow transfers. Check both ends before replacing hardware.

Spanning Tree Protocol protects redundancy

Two switch paths provide resilience, but layer 2 frames have no hop limit. Without protection, a broadcast can circle the loop repeatedly and consume the network. Spanning Tree Protocol, or STP, elects a root bridge and blocks selected redundant ports to leave one loop-free path.

The root bridge has the lowest bridge ID. Each non-root switch selects a root port toward that bridge. Each segment gets a designated forwarding port. STP blocks the remaining redundant ports. Rapid STP converges faster after a change, but the basic purpose remains loop prevention.

MAC-table flapping, many broadcasts, and high switch CPU point to a switching loop. STP keeps redundant links available while blocking the links that would form the loop.

Frame size must fit the whole path

Jumbo frames use an MTU larger than the usual 1500 bytes, often about 9000 bytes. Storage or data center traffic may use them to reduce overhead. Every device and link in the path must support the chosen MTU. One smaller link can drop or fragment traffic, depending on the protocol and settings.

A story: Leon connects a new floor

  1. Leon creates VLAN 30 in the switch database and assigns staff access ports to it.
  2. He permits VLAN 30 across the 802.1Q trunk to the distribution switch.
  3. He creates the VLAN 30 SVI on the layer 3 switch so staff can reach other networks.
  4. He leaves redundant uplinks in place, and STP blocks one until a forwarding link fails.

Choose bands, channels, encryption, authentication, antennas and AP types for a wireless scenario.

The job: Wireless design gives users a usable signal without letting neighboring radios interfere, then protects access with the right authentication, encryption, and access-point design.

Channels need room to breathe

A Wi-Fi channel uses a slice of radio spectrum. A wider channel width can carry more data, but it consumes more spectrum and leaves fewer channels for nearby access points. In a crowded office, 20 MHz or 40 MHz channels often work better than 80 MHz channels because nearby radios have more room to avoid each other.

On 2.4 GHz in the United States, channels 1, 6, and 11 do not overlap at the common 20 MHz width. Nearby access points should use a plan that repeats those non-overlapping channels instead of choosing adjacent channel numbers such as 1 and 3. Local regulations set which channels and power levels are legal.

802.11h covers 5 GHz features that respond to regulatory requirements. Dynamic Frequency Selection checks for radar and moves a Wi-Fi channel if necessary. Transmit Power Control limits radio power when rules require it.

More channel width is not always better. It trades available channels for peak throughput. Non-overlapping channels reduce adjacent access-point interference.

Choose the band for the space

2.4 GHz reaches farther and passes through walls better, but it has little non-overlapping spectrum and shares space with many consumer devices. 5 GHz usually provides more channels and higher capacity, with less range. 6 GHz adds clean spectrum for Wi-Fi 6E and Wi-Fi 7 clients, but its range is shorter and it requires WPA3 for Wi-Fi certification.

Band steering encourages dual-band or tri-band clients to use 5 GHz or 6 GHz when they support it. This can preserve 2.4 GHz for older or distant devices. It does not give an incompatible device a new radio.

Pick 2.4 GHz for reach and compatibility, 5 GHz for common higher-capacity office use, and 6 GHz for supported clients where clean spectrum matters. Confirm coverage with a site survey rather than guessing from a floor plan.

Analogy

Imagine several conversations in nearby rooms. Wider channels are larger rooms, but fewer rooms fit on the floor. Non-overlapping channels put conversations in separate rooms. Band steering asks a person who can use a quieter upstairs room to move there. Radio signals fade and collide in ways the room analogy cannot show.

Names, network shapes, and security

An SSID is the network name a user sees. A BSSID identifies one radio, usually by its MAC address. An ESSID lets several access points advertise the same SSID so a client can roam through one wireless network.

In infrastructure mode, clients connect through an access point. An ad hoc network links clients directly without an AP. A mesh uses APs that relay traffic to each other. A point-to-point wireless link bridges two fixed locations, such as separate buildings.

WPA2 uses AES-CCMP. WPA3 uses SAE for personal networks and offers a stronger enterprise mode. A PSK is one shared password, which is simple but difficult to revoke for one departed user. Enterprise authentication uses 802.1X and RADIUS so each person has an individual identity. A captive portal is a guest web page for terms, payment, or sign-in before general access.

Use WPA3-Enterprise with 802.1X when an organization needs individual wireless credentials. A captive portal manages guest access, but it does not replace strong Wi-Fi encryption or authentication.

Antennas and access-point management

An omnidirectional antenna spreads coverage around an access point, which suits a central office location. A directional antenna concentrates energy in one direction for a hallway, warehouse aisle, or building-to-building link. The right antenna follows the coverage shape, not the desire for maximum power.

An autonomous AP stores its own configuration. A lightweight AP receives centralized control from a wireless LAN controller, which simplifies consistent SSIDs, security, and channel plans across many APs.

A story: Noor plans conference Wi-Fi

  1. Noor finds that 2.4 GHz is crowded, so she assigns nearby 2.4 GHz APs to channels 1, 6, and 11.
  2. She uses 5 GHz with narrower channels in the busy conference area and band steering for compatible clients.
  3. Employees join WPA3-Enterprise with their own 802.1X credentials, while visitors see a separate guest SSID and captive portal.
  4. Lightweight APs report to the controller, which applies the same channel and security policy across the floor.

Plan a wiring closet: MDF vs IDF, racks and airflow, patch panels, power (UPS/PDU), and environmental controls.

The job: A physical installation keeps network equipment organized, powered, cool, secure, and reachable for repair. A sound room design prevents small facility problems from turning into an outage.

Put equipment in the right room

The main distribution frame, or MDF, is the central network room. It commonly holds the provider handoff, core switching, and the links that join a building or campus. An intermediate distribution frame, or IDF, is a smaller wiring closet that serves a floor, wing, or nearby area and connects back to the MDF.

Putting access switches in nearby IDFs keeps horizontal cable runs practical. The MDF remains the main aggregation point. The names describe network roles, not the size of a room.

An MDF is the central distribution location. An IDF is a local distribution point that uplinks to the MDF. A new floor commonly needs an IDF, not another MDF.

Rack equipment for service and airflow

Most network gear mounts in a 19-inch rack. Height is measured in rack units, where 1U is 1.75 inches. Leave enough room to route cables, label ports, and remove a failed device without disturbing neighboring equipment. Lockable racks restrict physical access to switches and servers.

Equipment has a designed airflow direction. Match port-side intake or exhaust to the room's hot-aisle and cold-aisle arrangement. Typically, equipment fronts face the cold aisle so they take in cool air, while warm exhaust goes to the hot aisle. Mixing airflow directions can recirculate hot air into an intake.

A rack is more than a place to stack devices. It must provide the right width and height, controlled access, cable management, and an airflow direction that matches the room.

Analogy

Think of a network room like a library's shelving and climate system. The catalog tells you where each item belongs, shelves keep it reachable, locks protect it, and ventilation keeps the room safe for the collection. Network equipment consumes power and produces heat, so it needs electrical and environmental planning that books do not.

Terminate permanent cable runs cleanly

Permanent copper cable runs end on a patch panel. Short patch cables then connect the matching panel ports to switch ports. This protects fixed cabling from repeated moves and makes tracing a wall jack back to a switch easier.

Fiber runs terminate on a fiber distribution panel. The panel protects, organizes, and presents the fiber for patching to optics. Label both ends of every copper and fiber run so a technician can follow the documentation during an outage.

Use patch panels for permanent copper runs and fiber distribution panels for permanent fiber. Patch cords are the short, replaceable links between a panel and active equipment.

Plan power before plugging in equipment

A UPS supplies battery power for a short outage and allows equipment to shut down cleanly. It does not replace a generator for a long utility failure. A PDU distributes power within a rack. A managed PDU can report load and switch outlets remotely.

Add each device's expected wattage, then compare the total with the circuit, PDU, and UPS ratings. Keep a margin rather than planning for full capacity. Verify voltage too: equipment and circuits may use 120 V, 208 V, or 240 V depending on the site. A plug that fits is not proof that the circuit has enough capacity.

Control the room environment

Equipment needs stable temperature and humidity. Too much heat shortens component life or causes shutdowns. Very low humidity raises the risk of electrostatic discharge. Excessive humidity can lead to condensation and corrosion. A common practical target is roughly 64 to 80 °F and 40 to 60 percent relative humidity, while vendor requirements set the final limits.

Water can damage energized equipment. A clean-agent gas system can suppress a fire without soaking racks. A pre-action sprinkler system keeps water out of the pipes until detection conditions are met, reducing the chance of an accidental discharge. The correct choice follows the site's fire code and equipment risk.

  1. Mateo places access switches in a lockable rack in the third-floor IDF and documents its fiber uplink to the MDF.
  2. He lands the building cables on labeled patch panels and uses short patch cords to the switches.
  3. He checks that the switches take cool air from the cold aisle and exhaust into the hot aisle.
  4. He totals the switch and PoE load before selecting the PDU and UPS, then confirms the room has environmental monitoring and suitable fire suppression.
