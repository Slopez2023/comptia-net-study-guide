Network Operations

This chapter covers keeping a network running: documenting it, monitoring it, recovering it, and the services every device depends on (DHCP, DNS, time). DNS records and DHCP are tested heavily.

Know which document answers which question, and how life-cycle, change and configuration management work.

Rack diagramWhat's in each U of each rack?

  • Life cycle: EOL = no longer sold. EOS = no more patches or support, so it's a security risk and should be replaced. Keep OS and firmware patched. Decommissioning = wipe or destroy data, update the inventory.
  • Change management: submit a request → review and approve (CAB) → schedule a maintenance window → keep a rollback plan → document.
  • Configuration management: the production config (running now), the backup config (a saved copy), the baseline / golden config (the approved standard to compare against).
Watch for

"Which VLAN and subnet is the server on?" → logical diagram. "Which switch port does office 204 connect to?" → physical diagram or cable map.

Pick the right monitoring tool: SNMP, flow data, packet capture, syslog/SIEM, or port mirroring.

MethodWhat you getUse it when…

  • SNMPv2c uses community strings (sent in plaintext, like passwords). SNMPv3 adds authentication and encryption. Always choose v3.
  • Baseline = what "normal" looks like. Anomaly alerts fire when traffic strays from the baseline.
  • Solution types: network discovery (ad hoc or scheduled), traffic analysis, performance, availability (up/down), and configuration monitoring (detect changes).
Watch for

"Device sends an alert when an interface goes down" → SNMP trap. "See which hosts use the most bandwidth" → NetFlow, not a packet capture.

Use RPO, RTO, MTTR and MTBF correctly, and match cold, warm and hot sites to budget and recovery speed.

SiteReady?CostRecovery
ColdEmpty room with power and network only$Days to weeks
WarmHardware in place, data somewhat out of date$$Hours to days
HotFully running mirror with current data$$$Minutes
  • MTBF = mean time between failures (higher is better, so it measures reliability). MTTR = mean time to repair (lower is better).
  • Active-active = all nodes carry load at once. Active-passive = a standby waits and takes over on failure.
  • Tabletop exercise = talk through a scenario around a table, with no systems touched. Validation test = actually fail over or restore to prove the plan works.
Watch for

"Can't lose more than 1 hour of data" = RPO of 1 hour, so back up at least hourly. "Must be back up within 4 hours" = RTO.

Configure DHCP (scope, reservations, relay), explain SLAAC, read DNS records, and know DNSSEC, DoH/DoT and the time protocols.

  1. D · Discover
    Client → broadcast: "Any DHCP servers?"
  2. O · Offer
    Server → "You can have 192.168.1.50"
  3. R · Request
    Client → "I'll take .50, please"
  4. A · Acknowledge
    Server → "It's yours for the lease time"

UDP 67 (server) / 68 (client). Discover is a broadcast, and routers don't forward broadcasts. That's why remote subnets need a DHCP relay / IP helper.

  • DHCP terms: scope = the pool of addresses. Exclusions = addresses inside the pool that are never handed out. Reservation = always give this MAC the same IP. Lease time = how long the address is held. Options = gateway (3), DNS (6) and others.
  • SLAAC (IPv6): the host builds its own address from the router's prefix (router advertisement) plus its interface ID. No DHCP server needed.
  • DNS roles: recursive resolver = does the lookups for you. Authoritative = owns the answer for a zone. Non-authoritative = a cached answer. Primary = editable zone copy, secondary = read-only copy received by zone transfer.
  • Forward zone = name → IP. Reverse zone = IP → name (PTR). The hosts file is checked before DNS.
  • DNSSEC = signs records so they can't be forged (integrity, not privacy). DoH (HTTPS 443) / DoT (TLS 853) = encrypt queries (privacy).
  • NTP (UDP 123) = clock sync, accurate to milliseconds. PTP = sub-microsecond, needs hardware support. NTS = authenticated (secure) NTP.
Watch for
  • Clients on a new floor or VLAN get APIPA addresses → missing DHCP relay / ip helper.
  • Printer needs the same IP every time but stays on DHCP → reservation.
  • Email isn't arriving → check the MX record. Email marked as spoofed → TXT (SPF).

Choose the right VPN and remote management method: site-to-site vs client, split vs full tunnel, in-band vs out-of-band.

Site-to-site VPNRouter or firewall to router or firewall. Always on, connects whole offices
Client-to-site VPNA remote user's device to the office. Uses client software, or is clientless (in the browser, over TLS)
Full tunnelAll traffic goes through the VPN, so corporate security inspects everything
Split tunnelOnly corporate traffic uses the VPN. Internet goes direct, which saves bandwidth but means less control
Jump box / hostOne hardened server you connect to first, then manage everything else from it
Out-of-band (OOB)A separate management path (console server, cellular modem) that works even when the production network is down
  • Connection methods: SSH (encrypted CLI, port 22), GUI (web/HTTPS), API (automation), console (a direct serial or USB cable, used for first setup or recovery).
  • In-band management uses the same network as user traffic. Out-of-band uses a dedicated path.
Watch for

"Need to reach a router after a bad config took down the network" → out-of-band / console. "Remote users' video calls slow down the VPN" → split tunnel.
